# Reproducing the metrics behind the paper

**This is a code-only release** (see the statement in [`README.md`](../README.md)):
it ships the code that computes the metrics behind the paper's figures, but ships
no data and no metric files. They are regenerated by running the scripts below.

This is the human-readable companion to [`experiments.yaml`](../experiments.yaml),
the machine-readable manifest that is the single source of truth linking each
experiment to the figures it underlies. The table below maps each **paper
figure** (by its `\label{...}` key) to the experiment and the compute scripts
that persist its underlying metrics, and states what a reader can run.

> Looking for intuition rather than exact reproduction? The Colab-ready guided
> tours in [`notebooks/`](../notebooks/) demo the readout-swap lag and the
> trajectory-crosscoder instrument live on public checkpoints.

## How to read this

The pipeline has three stages (see the `Makefile`):

1. **Extract** snapshots from public Hugging Face checkpoints. Pythia `W_U`
   snapshots are auto-extracted on cache miss by the trainer
   (`readout.crosscoder.wu_adapter.load_wu_snapshot`); OLMo-2 is pre-extracted with
   `experiments/crosscoders/crosscoder_olmo/scripts/extract_wu_olmo.py`;
   `scripts/extract/` holds the remaining extraction helpers (W_E, h_LN,
   firing rates, the OLMo eval corpus). Network + disk; CPU is fine for 160M.
   Pre-extracted caches are also released at
   `hf.co/datasets/hematteo/wu-crosscoder-snapshots`.
2. **Train** a trajectory crosscoder on the snapshots
   (`scripts/train/train_crosscoder.py`). GPU needed beyond 160M. The trained
   dictionaries of the paper are released at
   `hf.co/hematteo/parameter-trajectory-crosscoders` (see [DATA.md](DATA.md)).
3. **Analyze**: each experiment computes and **persists** the metrics behind
   its figures (CSV/JSON/`.pt`) by running the data-producing scripts in
   `experiments/<topic>/<id>/scripts/`. When run, the per-figure metric sidecars
   land under the experiment's `derived/` tree and the bulkier runtime outputs
   under its `results/` dir; both are gitignored and **not shipped** in this
   code-only release. These computed metrics are the reproducible artifacts.

No figure rendering happens in this repo. Each experiment's `scripts/` derive
and persist the numbers behind its figures; the figures are assembled in the
paper LaTeX tree from metrics produced that way.

**What ships in this repository:** all source code, the test suite (runs with no GPU
and no data), and the manifest. **What does not ship:** the `W_U` snapshots,
trained crosscoders, and aggregate tensors (large, read from `UM_SSD_ROOT`; see
[DATA.md](DATA.md)), **and the per-figure metric sidecars** (CSV/JSON/`.pt`),
which are regenerated by running the analyze-stage scripts rather than committed.
Reproducing a figure end-to-end therefore means running stages 1 and 2 first, or
downloading the released artifacts.

> Quickest check of the code itself: `make install && make test`. This needs no
> data and confirms the library and the vendored crosscoder import and run.

## Notes

- All paper figures are rendered in the paper LaTeX tree from the metrics these
  scripts produce; this repository computes those metrics on run but ships none
  of them, and ships no figure-rendering code.
- `make audit` (`scripts/audit/check_layout.py`) checks that every experiment
  directory has a manifest entry and that every path the manifest names exists.
  This release ships no `paper/`, so the label-coverage check against the paper
  source is skipped.
- Items marked "paper only" are listed under `paper_only_labels` in
  `experiments.yaml`: the schematics (Figure 1, Figure B.1) and the hand-typeset
  tables (Tables 1, 2, A.1, B.1, C.2, E.1, G.1). No experiment produces them, but
  the numbers they quote come from the experiments above.
